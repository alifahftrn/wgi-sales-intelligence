# Canonical Product Mapping V1

Additive patch for WGI Adapter V2 + MySQL 14-table patch. Copy all files into the project root. No existing files replaced; no new dependency. Uses existing PyYAML and Django. No database reads/writes, no migration.

Run `python -m unittest discover -v`, `python manage.py check`. Then run `python manage.py map_sales --source mysql --run-id <successful extract run ID>`; use `--source excel` for the demo Extract run. A run ID is explicitly required. Existing canonical run output is not overwritten; extract again to obtain a fresh ID.

Output: `.local/canonical/<source>/<run-id>/` containing `produk.jsonl`, `quarantine.jsonl` (line references and reasons), `manifest.json` (scope, counts, checksums and unmapped datasets). Raw product file checksum, count and column set are checked before publishing. `READY` means product attributes pass this stage only; it does not mean loaded. `INCOMPLETE` means the demo lacks required dimension attributes; must not be loaded. Invalid data is quarantined, duplicate normalized valid keys fail the run. Partial is expected for three-column Excel demo. The other datasets are explicitly not mapped yet. Decimal values are emitted as exact strings; product codes as text. Source identity is separated by MYSQL/EXCEL demo namespace; cross-source identity and multiple same-type systems require a future explicit registry/crosswalk. No historical validity or SCD2 versions are inferred. Mapping requires exact volume consistency and current 2W/4W, Top/Mid/Low domains. Review rejected records before loading. Keep `.local` private.
